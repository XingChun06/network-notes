一次网页请求经历了什么

从在地址栏按下回车，到页面完整出现，浏览器需要连续完成名称解析、连接建立、资源请求和渲染。

2026 年 10 月 8 日 约 6 分钟阅读

网页看起来像一份已经排好的电子文档，实际却是浏览器在很短时间内取回多种资源，再按规则组合出的结果。理解这条路径，有助于把 HTML、服务器和 HTTP 放进同一幅图里。

第一步：把域名变成地址

浏览器首先需要知道服务器位于哪里。DNS 会把容易记忆的域名转换成 IP 地址。浏览器会优先检查已有缓存；没有命中时，系统再向 DNS 解析器查询。这个过程类似在通讯录中根据姓名查找号码。

第二步：建立安全连接

获得地址后，浏览器与服务器建立连接。传统的 HTTP/1.1 和 HTTP/2 通常基于 TCP；HTTPS 还要完成 TLS 握手，用于协商加密方式并验证服务器证书。HTTP/3 则把传输建立在 QUIC 之上。

第三步：发送 HTTP 请求

连接就绪后，浏览器发送请求。请求中包含方法、路径和请求头，例如：

GET /posts/a-web-request.html HTTP/1.1
Host: example.github.io
Accept: text/html

GET 表示读取资源，路径指出需要的页面，Host 用来标识目标网站。服务器处理请求后返回状态码、响应头和 HTML 正文。

第四步：继续获取页面资源

浏览器解析 HTML 时，会发现样式表、脚本和图片地址，于是继续发起请求。现代协议可以在同一连接中并发传输多个资源，减少反复等待。开发者工具的 Network 面板会把这些请求逐条列出。

第五步：解析并绘制页面

浏览器把 HTML 转换成文档结构，把 CSS 转换成样式规则，再计算每个元素的位置和尺寸。最后，它把文字、颜色和图片绘制到屏幕上。JavaScript 还可以在页面出现后继续改变内容和交互状态。

在本次实验中观察协议

  1. 打开部署后的公网网页，而不是本地预览地址。
  2. 按 F12 打开开发者工具，选择 Network 面板。
  3. 刷新页面，在表头启用 Protocol 列。
  4. 找到类型为 document 的主页面请求，记录协议值。

http/1.1、h2 和 h3 分别对应 HTTP/1.1、HTTP/2 和 HTTP/3。最终结果取决于部署平台、浏览器和网络环境，应以实际观测为准。
